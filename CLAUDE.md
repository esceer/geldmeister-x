# Geldmeister X

Personal, local-only expense tracker (Expo SDK 58, React Native, TypeScript strict). Android first; keep code iOS-compatible. Setup, commands and structure: `README.md`. Design source of truth: `docs/design/` (Midnight Glass, dark only; ask before inventing a light theme).

## Domain rules

- Expenses only, no income.
- Money is integer minor units plus a currency code; never floats. Decimals per currency (`currencies.decimals`: HUF 0, EUR 2).
- Each currency is an isolated world: expenses, budgets, recurring items and reports are scoped to the active currency (`useSettings().currency`). Never sum or convert across currencies.
- New expenses default to the active currency but can pick any tracked one. Hiding a currency in Settings sets its `deletedAt`; its data stays and returns when it's tracked again.
- Categories are shared across currencies. Deleting one archives it (`deletedAt`): it leaves pickers, its budgets and recurring items stop, and past expenses keep it.
- Tags belong to a category. An expense can have several tags, so tag totals may overlap.
- Deletes are soft (`deletedAt`) with an Undo snackbar and no confirm dialog, except swipe-to-delete on expense rows, which asks first. Tag links (`expense_tags`) are soft-deleted too.
- Editing an expense never changes its currency. Editing a recurring item affects future occurrences only.
- Recurring occurrences are counted from `startDate` (the 31st clamps to short months without drifting) and generated on app start and on return to foreground, catching up missed ones.
- Budget progress counts only categories that have a budget.
- Reports are on screen only (no export), laid out for copying into Excel by hand.
- Sync-ready data: UUID ids, `createdAt`/`updatedAt`, `deletedAt` on every row.

## Conventions

- Routes in `src/app` stay thin. Feature code lives in `src/features/<feature>/` (components, `hooks.ts` for reads, `queries.ts` for writes). Shared UI goes in `src/components/ui`; pure, unit-tested logic in `src/lib`.
- DB reads go through `useQuery(run, tables)` (`src/db/useQuery.ts`): synchronous Drizzle queries re-run when a watched table changes. Not Drizzle's `useLiveQuery`.
- Insert rows with `id: newId()` (`src/lib/id.ts`). The schema has no id default because `drizzle-kit` can't load `expo-crypto`.
- Schema change: edit `src/db/schema.ts`, then `npm run db:generate`. Migrations run on startup.
- Bottom sheets are root-level `transparentModal` routes (`expense`, `category`, `tag`, `recurring`, `budget`, `currency`, `language`) built on `components/ui/Sheet`.
- Every UI string goes in `src/i18n/en.json` and `hu.json`.
- Format money with `formatMoney`/`formatAmount` from `src/lib/money.ts`. Hermes ignores `currencyDisplay: 'narrowSymbol'`, so symbols come from a small map there.
- Before finishing: `npm run typecheck`, `npm run lint`, `npm test`.

## Gotchas

- Expo changes fast; check the SDK 58 docs (`docs.expo.dev/versions/v58.0.0/`) rather than memory.
- Expo Router 58 renders nothing for screens not declared in a layout (`<Tabs.Screen>` / `<Stack.Screen>`).
- Real blur works only on the nav pill (`BlurView` with a `BlurTargetView`, Android 12+). Android can't blur across screens, so sheets use the opaque `colors.sheet`.
- Keyboard: use `KeyboardAvoidingView` from `react-native-keyboard-controller` (`KeyboardProvider` is at the root). Content must stay in normal layout flow, not absolutely positioned, or it won't be lifted.
- After adding native libraries, rebuild with `npx expo run:android`. After changing `app.json`, icons or the splash screen, run `npx expo prebuild -p android --clean` first. App icons are generated by `docs/design/icon/make-icons.js`.
